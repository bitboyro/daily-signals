# Daily Signals v1.0.0

Daily Signals v1.0.0 is the first qualified release of the public-radio platform. It combines a Java 21 editorial and publication backend, PostgreSQL persistence, a Rust audio streamer, and a TypeScript listener/producer PWA. The reference system remains runnable without live news, speech or cloud credentials by using synthetic licensed fixtures and deterministic audio.

## Product scope

- Producers authenticate, review normalized candidates, edit a versioned script and pronunciation lexicon, generate and validate audio, approve a revision and publish it.
- Listeners can play today's edition, browse the archive and chapters, resume playback, share stable links, install the PWA and subscribe to the podcast feed in Romanian or English.
- Operators can install the five-service Compose model, configure the station, back up and restore PostgreSQL plus objects, migrate v0.x JSON/WAV state, monitor health and metrics, and follow documented incident/rollback procedures.
- Recordings are SHA-256 bound to manifests, stored behind an S3-compatible boundary and served with byte ranges, cache validators and safe missing-object behavior.

## Install or upgrade

For a clean installation, follow the [operator guide](../operations/installation.md) or run `./install.sh`. The base profile uses deterministic fixture speech; the optional Kokoro profile requires the pinned model and voice assets documented in the operator guide.

Existing v0.x installations must follow the [v0.x-to-v1 procedure](../operations/upgrade-v0-to-v1.md). It rehearses against the actual `v0.2.0` tag, imports settings and editions idempotently, copies recordings with read-back checksum verification, and defines the rollback boundary.

## Compatibility and boundaries

- Java 21 is the supported application runtime; Java 25 is exercised as a compatibility matrix entry.
- Node 22 and 24 qualify the web client; the package requires Node 22.18 or newer.
- PostgreSQL 17 is the reference database.
- The streamer is built from the pinned Rust stable toolchain and uses publication-manifest schema v2.
- Producer writes fail closed unless OIDC or an explicit local-development reviewer token is configured.
- Live sources, production speech assets and cloud credentials are intentionally outside the reference release.

## Release evidence

The `v1.0.0` tag workflow builds the API and streamer images, listener ZIP and source-complete install bundle. It runs Java/PostgreSQL, Rust, web, browser, accessibility, cross-process, container and deployment qualification, then emits a source-bound manifest containing contract, audio and report digests.

The pull-request matrix remains the full correctness reference while Decision Lab operates in shadow. Optimizer plans are advisory and retain selected-job explanations; the `run-all-checks` label remains the explicit human override.

Known operational limitation: public dependency repositories can rate-limit concurrent clean runners. Such failures occur before project compilation and are treated as infrastructure evidence; targeted reruns are retained rather than rewriting the source result.
